# 変更内容の HTML 化とコミット

`git add -A && git commit` を出力確認なしで任せきりにしない。必ず人が内容を見てからコミットする。

## 手順

1. `git status` と `git diff`（ステージ済みは `git diff --cached`）を確認する。`.env` などの秘密ファイルが含まれていないかも見る。
2. **レビュー**: `/code-review`（バグ・改善点）と `/security-review`（脆弱性・秘密情報の混入）の両方を実行する。観点が違うため両方かける。指摘があれば直し、`git diff` で再確認する。
3. 変更を、**変更内容（目的）ごとのグループ**に分類する。ファイル単位ではなく「何のための変更か」で分け、各グループに関係するファイルを割り当てる。
4. 固定テンプレート `.claude/skills/commit-diff-html/template.html` をコピーして使う（レイアウトや CSS は変えない）。一時ディレクトリに出力し、リポジトリには置かない。
   ```bash
   out="$(mktemp -d)/changes.html"
   cp .claude/skills/commit-diff-html/template.html "$out"
   ```
5. コピーしたファイルの次のプレースホルダーを置換する。
   - `{{TITLE}}`: 変更の要約タイトル（1 行）
   - `{{ISSUE}}`: 関連 Issue（例: `#123`。なければ `Issue なし`）
   - `{{DATE}}`: 日付（`YYYY-MM-DD`）
   - `{{SUMMARY}}`: 何を・なぜ変えたかの要約（1〜3 行）
   - `{{FILE_LIST}}`: 変更ファイルごとの `<li>`（追加 `add`／変更 `mod`／削除 `del` のバッジ付き）。**変更が大量でも全件載せ、省略しない**
   - `{{CHANGE_GROUPS}}`: 変更内容ごとの `<section class="group">`。タイトル、意図（1〜2 文）、関係ファイルのチップ、差分の抜粋を入れる
     - 差分は全量を載せず、変更の意図が伝わる**要所だけをピックアップ**する（追加行 `add`、削除行 `del`、ハンク `hunk`）
     - 変更が少ないときは差分を多めに、大量のときは各グループ 1〜2 箇所に絞り、省略した分は `note` に「ほか N ファイルは同種の変更のため省略」と書く
   - 差分の内容は必ず HTML エスケープする。置換後に `{{` が残っていないか確認する
6. `open "$out"` でブラウザに表示し、パスをユーザーに伝える。
7. ユーザーの承認を待つ。承認後、対象ファイルを個別に `git add` し、コミットする。メッセージは変更の理由が分かるように書く。
8. 修正指示があれば直して、手順 4 からやり直す。

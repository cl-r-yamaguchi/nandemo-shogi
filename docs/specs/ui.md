## 1. 方針

- **ポップなゲームらしさ**: 丸みのある形、はっきりした色、弾むような動き。
- **すべて自作**: ダイアログ、プルダウン、ボタン、入力欄など、OS・ブラウザ標準の見た目の部品は使わない（`<select>`、`alert`、`confirm`、`<dialog>` の標準の見た目、標準のスクロールバー、標準のツールチップを含む）。
- **非連続に動かない**: 見た目の状態は、必ずアニメーションでつなぐ。表示・非表示、位置、大きさ、色、HP の増減など、値が変わるものはすべて補間する。
- **全情報の公開**: 相手のドロー結果・持ち駒・残り時間も、常に見える。

## 2. 画面一覧と遷移

| 画面 | 目的 | 次の画面 |
| --- | --- | --- |
| タイトル | 表示名の入力、「あそぶ」 | ルール設定 |
| ルール設定 | 人数（2〜4。初期値 4）と AI の強さ（1〜3。初期値 2）を選ぶ | 待機ルーム |
| 待機ルーム | 席の状況を見る。Go で開始、退出 | 対戦、ルール設定（退出） |
| 対戦 | ゲームをする | 結果 |
| 結果 | 順位・勝者・終了理由。「もう一度」「タイトルへ」 | ルール設定、タイトル |

- 画面の切り替えは、フェード・スライドなどで、連続的につなぐ。
- ブラウザのリロードでは、対戦中・待機中なら、同じ画面に復帰する（[online.md](online.md) の再接続）。

## 3. 対戦画面

### 3.1 レイアウト

```
┌────────────────────────────────────────────────────┐
│ [プレイヤー一覧: 色・マーク・名前・城HP・残り時間]   [ログ ▾] │
│                                                    │
│                  3D の盤（中央）                    │
│                                                    │
│ [持ち駒トレイ]                      [行動ボタン]    │
└────────────────────────────────────────────────────┘
```

- **プレイヤー一覧**: 席の順。自分は強調。手番のプレイヤーは、枠が光る。各行に、色とマーク、名前（人間／AI の区別を含む）、城の HP、脱落の有無。手番の人の行に、残り時間のバー（秒数つき）。
- **持ち駒トレイ**: 自分の持ち駒を、種類ごとにまとめ、個数を表示する。他プレイヤーの持ち駒は、プレイヤー一覧の行を開くと見られる。
- **行動ボタン**: 「確定」「キャンセル」「投了」。
- **ログ**: 直近の出来事（攻撃、捕食、成り、脱落、時間切れ、切断・AI 代行）を、新しい順に並べる。

### 3.2 プレイヤーの識別

プレイヤーは、4 色とマークの組で識別する。色だけに頼らない。

| 席の順 | 色 | マーク |
| --- | --- | --- |
| 1 | 赤 | ● |
| 2 | 青 | ▲ |
| 3 | 緑 | ■ |
| 4 | 黄 | ★ |

駒のベース（台座）に、プレイヤーの色とマークを付ける。

### 3.3 3D 表示

- **盤**: 16x16 の格子。市松模様、角の丸い台座、軽い影。
- **駒**: 種類ごとに、デフォルメしたかわいい 3D モデル。占有範囲（大きさ・向き）にぴったり収まる大きさ。台座にプレイヤーの色とマーク。向きは、モデルの顔・体の向きと、台座の矢印で示す。
- **HP バー**: 駒の頭上に、常に表示する。HP が減ったとき、減った分が遅れて消える。
- **カメラ**: ドラッグで回転、ホイール・ピンチで拡大縮小。初期位置は、盤全体が見える斜め上で、自分の城の側が手前。自分の手番になったときは、盤を見やすい位置へ、滑らかに寄る。
- **モデルの要件**: 低ポリゴン。1 種類あたりのファイルを小さく保つ。駒の追加は、モデルファイルの追加と、データ定義の追加だけで済む（[pieces.md](pieces.md)）。

## 4. 操作の流れ

自分の手番は、次の順で進む。確定するまで、サーバーには何も送らず、キャンセルできる。

### 4.1 ドロー・選択

1. 手番が始まると、画面の中央に、引いた 4 枚のカードが、順に飛んできて並ぶ。
2. 各カードには、駒の 3D モデル、名前、大きさ、攻撃力、HP、移動範囲を表示する。移動範囲は、カードの中のミニ盤で、駒を中心に動けるマスを色付きで見せる（直進の駒は、前方の線として見せる）。
3. カードにポインターを置く（タッチでは、タップして選ぶ）と、そのカードの移動範囲が、大きく見える。
4. 1 枚をタップ（またはドラッグ）して「この駒にする」を押すと、そのカードが、持ち駒トレイへ入り、残りの 3 枚は、消える。

### 4.2 行動

選択のあと、次の 3 つのどれかを行う。

- **配置**: 持ち駒トレイの駒をタップ → 盤上の置ける場所が色付きになる → 置く場所をタップ → 向きを選ぶ（駒の周りに 4 方向の矢印が出る）→ 確定。置けない（隣接していない・重なる）マスは、色が付かず、タップしても反応しない。
- **移動**: 盤上の自分の駒をタップ → 動ける範囲のマスが色付きになる → 行き先をタップ → 確定。
- **回転**: 盤上の自分の駒をタップ → 「回転」を押す → 駒の周りに 4 方向の矢印が出る → 向きをタップ → 確定。回転後に盤外・重なりが出る向きは、無効の見た目になる。

### 4.3 確認とダメージの予告

- 移動先に駒がいるとき（攻撃になるとき）は、確定前に、予告を表示する。予告は、攻撃される駒ごとに「与えるダメージ」「残り HP」「捕食される」を、駒の上に出す。攻撃した駒が動けるかどうか（すべて捕食されるか）も示す。
- 捕食が起きる行動のとき、成れる駒なら、確定前に、自作のダイアログで「成る／成らない」を聞く。成れない場合は聞かない。
- 自分の駒への攻撃、特に自分の城への攻撃は、「自分の駒を攻撃します」と、確認ダイアログを出す。
- 時間が少ない（10 秒以下）ときは、残り時間のバーが、色と動きで目立つ。

### 4.4 アニメーション（結果の見せ方）

行動が確定すると、サーバーから全員に結果が届く。結果は、次の順に、連続して見せる。

1. 駒が、移動先へ滑らかに動く（攻撃のみなら、攻撃して元の位置へ戻る動き）。
2. ダメージの数字が出て、HP バーが減る。
3. 捕食された駒が、縮んで消え、攻撃した人の持ち駒トレイへ飛ぶ。
4. 成りがあれば、駒が光って、成り先のモデルへ変わる（モデルの切り替えも、拡大・縮小でつなぐ）。
5. 脱落があれば、その人の駒が、順に消える。

他のプレイヤー（人間・AI）の手も、同じ見せ方にする。AI の手は、速く返ってきても、最低 1.5 秒かけて見せる（何が起きたか分かるように）。

## 5. 表示の規則

### 5.1 移動範囲のハイライト

- 駒をタップしたとき、動ける範囲のマスを、色付きで塗る。移動先に敵の駒があるマスは、攻撃を示す別の色（と形）にする。味方の駒がいるマスも、攻撃になるので、同じ攻撃の色。
- 色に加えて、模様・マークで区別する（移動 = 点、攻撃 = ×印）。
- 「直進」の駒は、前方の線と、行き着く先のマスを示す。

### 5.2 危険マーク（びっくりマーク）

- 駒の右上に、びっくりマーク（！）を付ける。付ける条件は、**その駒の持ち主以外のプレイヤーのいずれかが、その駒の現在の HP 以上のダメージを、1 回の移動で与えられる**こと（定義は [game-rules.md](game-rules.md) の 8 章、R-A0）。
- 判定は、いまの盤面の、他プレイヤーの全駒の合法な移動から計算する（`rules` の `threatened_pieces`）。配置は含めない。成りや、その後の手は考えない。
- 自分の駒だけでなく、他プレイヤーの駒にも付ける（誰の駒でも、狙われているかがわかる）。
- 計算は、wasm で、盤面が変わるたびに、全駒について行う。
- マークは、出現・消失をアニメーションでつなぐ（ぽんと弾む）。

## 6. 自作 UI 部品

標準の部品を使わず、次の部品を自作し、すべての画面で共通に使う。見た目は、デザイントークン（7 章）から決める。

| 部品 | 要件 |
| --- | --- |
| ボタン | 押下・ホバー・無効の状態を、アニメーションでつなぐ。キーボードで操作できる |
| ダイアログ | 背景を暗くし、中央に、弾むように現れる。閉じるときも、アニメーション。フォーカスを中に閉じ込め、Esc で閉じる（閉じてよいダイアログのみ） |
| セレクト（プルダウン） | 自作の開閉リスト。上下キーで選択、Enter で決定、Esc で閉じる。ルール設定の AI の強さなどで使う |
| ステッパー | 人数など、数値の増減。増減ボタンと数字の変化を、アニメーションでつなぐ |
| トグル・セグメント | 2〜4 個の選択肢から 1 つ。選択のしるしが、滑らかに移動する |
| 入力欄 | 表示名の入力。文字数の上限を超えたら、揺れて知らせる |
| トースト | 画面の隅に、一時的に出る通知。接続切れ、操作の拒否の理由など |
| ツールチップ | ポインターを置いたときの説明 |
| プログレスバー | 残り時間、HP |
| カード | ドローで引いた駒のカード |

- すべての部品は、キーボードで操作でき、フォーカスの位置が見え、役割を表す属性（ARIA）を持つ。
- 色だけで状態を伝えない（形・模様・文言を併用する）。

## 7. デザイントークン

見た目の値は、1 か所のトークン定義（CSS の変数）にまとめ、部品はそれを参照する。値の直書きをしない。

| 種類 | 方針 |
| --- | --- |
| 色 | 明るい背景に、彩度の高いアクセント。4 人の色は、赤・青・緑・黄（色覚の違いでも区別できるよう、マークを併用） |
| 形 | 大きめの角丸、太めの縁取り、軽い影 |
| 文字 | 丸みのある日本語フォントを、アプリに同梱する（外部サービスから読み込まない）。数字は、等幅の見やすいもの |
| 動き | 標準の長さ 150〜400 ミリ秒。移動・拡大は、少し弾むイージング。消えるときは、短く |

### アニメーションの例外

OS の「視覚効果を減らす」がオンのときは、アニメーションを、短く・小さくする（弾み・揺れをなくす）。それでも、値の変化は、補間でつなぐ（瞬間的な切り替えはしない）。

## 8. 操作デバイス

- マウスとタッチの、どちらでも、同じ操作ができる。ホバーでしか見られない情報は、タップでも見られるようにする。
- キーボードは、ダイアログ・セレクトなどの部品の操作に対応する。盤上の操作は、マウス・タッチを前提とする。

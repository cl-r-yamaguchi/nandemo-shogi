# Issue #14: rules: 行動の適用（`feature/14-rules-actions`）

PR #13 マージ後に着手。`rules` の第 2 段として、配置・移動・回転・攻撃・捕食・成り・パスと、手番の進行を実装する。

## やったこと

- `rules` に、行動の適用（`action.rs`）を実装した。`apply` は、元の状態を変えず、新しい状態と出来事の列を返す。
  - 配置（配置フェーズの城、対戦フェーズの持ち駒）、移動（直進を含む）、攻撃と捕食、成り、回転、パス、手番の進行。
  - 画面・AI 向けに、`legal_targets`（駒の移動先）、`legal_placements`（置ける位置と向き）、`has_legal_action` を公開した。
- `geometry.rs` に、占有範囲の間のすきまを求める `gap` を足した（城の間隔と、隣接の判定に使う）。
- テストは 98 件（このうち行動の適用が 47 件）。R- 番号ごとに確認している。

## 判断とその理由

- 出来事（`Event`）は、ダメージ・捕食・移動・成りを別々に返す。画面が順に再生でき、記録にもそのまま使えるため。
- 隣接の判定は `gap == 0`（辺・斜めで接するが、重ならない）で統一した。城の間隔（R-13）も `gap >= 3` で同じ関数を使う。
- 成れる駒は、現在の駒データでは 1x1 だけなので、「複数の駒に重なって動けないが、成る」場面は起きない。ルールとしては、捕食が起きれば、動いたかどうかによらず成れる実装にしてある。
- 時間切れ（R-31）、ドローと選択、脱落・勝敗は、この Issue のスコープ外。

## 未解決・次にやること

- ドローと駒の選択（手番の段階）、時間切れの処理。
- 脱落・勝敗・引き分け・投了・手番数の上限（R-90〜97）。
- 危険な駒（！マーク）の判定。
- `/code-review` の指摘を反映した。城の間隔は、他のプレイヤーの城だけが対象（R-13）。直進の探索は、盤の大きさの手数で打ち切る。`has_legal_action` は、置ける場所を 1 つ見つけた時点で終わる。
- 脱落・勝敗・手番数の上限・脱落した席の検査は、次の Issue で扱う（`apply` の説明に明記）。

# Issue #16: rules: 脱落・勝敗・終局（`feature/16-rules-finish`）

PR #15 マージ後に着手。脱落、終局、順位、投了、手番数の上限を `rules` に実装する。

## やったこと

- `rules` に、脱落・終局・順位・投了を実装した（`finish.rs`）。
  - 行動のあとに、城のないプレイヤーの脱落（R-90・R-91）、終局（R-93・R-94）、手番数の上限（R-95）を判定する。
  - 投了は、手番でなくてもできる関数 `resign`（R-96）。
  - 結果（`Outcome`）に、順位（同順位は同じ組）と終了理由を持たせた（R-97）。
- `state.rs` に、脱落の記録（`out_batches`）、結果（`outcome`）、`alive_players`、`advance_current` を足し、`validate` に脱落者の持ち物・記録の整合・結果の整合の検査を足した。
- テストは 123 件（脱落・終局・順位・投了・手番数の上限で 24 件）。

## 判断とその理由

- 手番数の上限（R-95）は、開始時の人数 × 100 に固定した。途中で脱落者が出ても変えない。上限が動くと、残りの手番数の見通しが立たなくなるため。`game-rules.md` にも明記した。
- 投了は、手番番号を進めない。行動ではないため。手番のプレイヤーが投了したときだけ、次の席へ手番を回す。
- 順位は、同時に脱落した人を同じ組にする。脱落の記録を「同じ行動で脱落した人の組」の並びで持つことで、順位の計算を単純にした。
- 既存の行動のテストは、対戦フェーズで城のないプレイヤーが脱落する仕様に合わせ、城を補ってから `apply` を呼ぶ補助関数を、テスト側に入れた。

## 未解決・次にやること

- ドローと駒の選択（手番の段階）、時間切れの処理。
- 危険な駒（！マーク）の判定。
- 性能: 状態の複製と、プレイヤーごとの走査が、行動ごとにある。AI の実装時に計測して、必要なら最適化する。
